# ЭПСИЛОН — MVP

Демонстрационная система управления разработкой: отдельные разделы дашборда, планирования, технологической карты, закупок, бюджета, качества, корректировок, отчётов и пользователей. Переключение проекта меняет контекст всех разделов. Круговые и радарная диаграммы показывают финансы, исполнение и профиль проекта.

## Технологическая карта

Раздел `/technology` показывает состав тестовой сборки выбранного проекта: подсистемы, ревизии, количество на изделие и партию, годные остатки, брак, детали в пути и готовность к сборке. В примере AURORA-02 теплоотвод и корпус готовы, датчики и жгуты блокируют сборку, GaN-модули ожидают поставки, а плата Rev D — верификации. ORBIT-01 и NOVA-03 имеют собственный состав.

Можно добавить компонент, изменить его с новой ревизией и обязательным обоснованием, запросить верификацию, зафиксировать результат с протоколом или сформировать валютную закупочную заявку. Запросы связаны с карточками канбана, бюджетными оценками, разделами закупок и качества. Прежние ревизии и основания изменений сохраняются; запросы старой ревизии требуют актуализации. Word, CSV для Excel и JSON включают состав, запросы и историю.

Это прототип: складские остатки и исходные финансовые данные — демонстрационный снимок. Запросы не меняют утверждённый бюджет, EAC, фактические расходы или наличие деталей. Брак не становится годным после успешного теста. Реальные поставки, приёмка, согласование закупок и прикрепление файлов не реализованы; поле документа хранит идентификатор или ссылку. Валютный курс в заявке — редактируемый сценарный курс, не рыночная котировка.

Канбан поддерживает добавление и редактирование карточек, перетаскивание и смену статуса в деталях карточки. Новые оценки формируют бюджетные заявки. Настройки пользователей, карточки и история отчётов сохраняются в `localStorage` текущего браузера. Это демонстрационная версия: общего backend-хранилища, авторизации и исполнения прав доступа пока нет.

Базовая валюта интерфейса — рубли. Word, CSV для Excel и JSON показывают финансовые суммы в **тыс. руб.**; формы ввода принимают рубли. Для демонстрационного перехода численные значения существующих бюджетов и оценок сохранены без пересчёта по рынку. Карточки, пользователи и история сохраняются, прежние обозначения базовой валюты обновляются при загрузке и повторной выгрузке. Закупки доступны в RUB и USD, итог рассчитывается в рублях по явно указанному курсу. Сценарный курс для новых заявок — 92 руб./USD, не рыночная котировка; курс старых заявок не переопределяется.

## Состав

- `dist/index.html`, `dist/assets/` — интерфейс, маршруты, данные и SVG-иконка ЭПСИЛОН;
- `Dockerfile`, `deploy/nginx.conf` — Nginx-контейнер, работающий без root и слушающий порт 8080;
- `compose.yaml` — изолированный контур из веб-сервиса и отдельной PostgreSQL-БД.

## Локальный просмотр

Выполните `node scripts/preview.mjs` и откройте `http://127.0.0.1:4195`. Сервер поддерживает прямые ссылки на разделы, например `/planning` и `/users`.

Проверка логики карты и выгрузок: `node scripts/test-technology.mjs`.

## Docker Compose / Dokploy

1. Скопируйте `.env.example` в `.env` и задайте надёжный пароль БД.
2. Выполните `docker compose up --build`.
3. В Dokploy направьте домен на сервис `web`, внутренний порт `8080`. Для локального Docker-просмотра добавьте привязку порта `127.0.0.1:8080:8080` в отдельный Compose override.

PostgreSQL не публикуется наружу: её можно использовать для следующего этапа, когда данные из прототипа будут перенесены из интерфейса в прикладную модель.
